# Key Concepts Learned

### Unit Testing
Unit Testing verifies individual components or functions of an application. It is usually performed by developers before integrating the code with other modules.

### Integration Testing
Integration Testing ensures that different modules or services work together correctly after being combined.

### System Testing
System Testing evaluates the complete application to ensure it meets the specified functional and non-functional requirements.

### User Acceptance Testing (UAT)
User Acceptance Testing is performed by end users or clients to confirm that the application satisfies business needs before release.

---

# Test Types

### Smoke Testing
Smoke Testing verifies that the most important features of an application work correctly before detailed testing begins.

### Sanity Testing
Sanity Testing confirms that a specific bug fix or small change works as expected without testing the entire application.

### Regression Testing
Regression Testing ensures that recent code changes have not introduced new defects into existing functionality.

### Retesting
Retesting is performed to verify that a previously reported defect has been successfully fixed.

### Exploratory Testing
Exploratory Testing involves actively exploring an application without predefined test cases to discover unexpected defects.

# Biggest Lesson

Although Smoke Testing, Sanity Testing, Regression Testing, and Retesting are closely related, each has a different objective.

Understanding when to use each testing type is an essential skill for every QA Engineer.

---

# Challenges Faced

Initially, I found it difficult to distinguish between Regression Testing and Retesting. After studying examples, I now understand that:

- Retesting verifies a specific bug has been fixed.
- Regression Testing checks whether recent changes have affected other parts of the application.
