# Key Concepts Learned

## Test Plan

A Test Plan is a project-specific document that describes:

- What will be tested
- How testing will be performed
- Who is responsible for testing
- Testing schedule
- Risks and deliverables

I learned that the Test Plan acts as a roadmap for the testing process.

---

## Test Strategy

A Test Strategy is a high-level document that explains the overall testing approach for a project or organization.

Unlike a Test Plan, a Test Strategy is generally reused across multiple projects and focuses on the overall testing methodology rather than project-specific details.

---

## Difference Between Test Plan and Test Strategy

One important lesson today was understanding the difference between these two documents.

| Test Plan | Test Strategy |
|-----------|---------------|
| Project-specific | High-level approach |
| Created for a specific project | Often used across multiple projects |
| Includes schedule, scope and resources | Defines overall testing methodology |

This was initially confusing, but after reviewing examples I now understand their different purposes.

---

## Entry Criteria

Entry Criteria are the conditions that must be met before testing can begin.

Examples include:

- Test environment is ready.
- Test data is available.
- Requirements are approved.
- Application build is deployed.

---

## Exit Criteria

Exit Criteria define when testing can be completed.

Examples include:

- All planned test cases executed.
- Critical defects resolved.
- Test Summary Report completed.

---

## Test Estimation

Test Estimation is the process of estimating the effort, time and resources required to complete testing activities.

I learned that estimation depends on:

- Project size
- Application complexity
- Team size
- Available time
- Testing scope
