# Topic

API Validation, Assertions, and Postman Tests

---

## What I Learned

Today I learned how to validate API responses instead of only sending requests.

I explored how QA Engineers use Postman to verify:

- HTTP status codes
- Response times
- JSON response data
- Response headers
- Automated API assertions

I also learned that a successful HTTP 200 response does not always mean the API is working correctly. The response content must also be validated against the expected result.

## Key Takeaways

- API validation is an important part of backend testing.
- Assertions automate response verification.
- Postman simplifies API testing and validation.
- QA Engineers should validate both the response status and the response content.
- Automated API checks improve testing efficiency and consistency.

## Reflection

Today's lesson helped me understand that testing an API goes beyond checking for a successful status code. Validating the response body, headers, and response time provides greater confidence that the API behaves as expected.

I feel more confident using Postman and look forward to learning more advanced API testing techniques.
