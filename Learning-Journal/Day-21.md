# Day 21 — Static vs Dynamic Testing

## Date

21 August 2026

## Topic

Static vs Dynamic Testing

## What I Learned

Today, I learned the difference between Static Testing and Dynamic Testing.

Static Testing involves reviewing software-related work products without executing the software. Examples include reviewing requirements, acceptance criteria, test cases, documents, and source code.

Dynamic Testing involves executing the software and comparing the actual behaviour with the expected result. Examples include testing login functionality, cart functionality, checkout flows, and APIs.

I also learned four common review types:

- Informal Review
- Walkthrough
- Technical Review
- Inspection

## Practical Exercises Completed

- Classified activities as Static or Dynamic Testing.
- Identified different review types.
- Applied Static and Dynamic Testing concepts to SauceDemo scenarios.
- Analyzed an unclear checkout requirement.
- Practiced interview questions about Static and Dynamic Testing.

## Key Insight

Testing does not only begin when an application is ready to run.

QA can help identify issues earlier by reviewing requirements, documents, and other work products before software execution.

## Challenge

The main challenge was understanding how Static Testing can identify potential defects without running the application.

## Key Takeaway

> Static Testing = Review without executing the software.

> Dynamic Testing = Execute the software and test its actual behaviour.
