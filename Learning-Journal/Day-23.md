# Day 23 — Black Box vs White Box Testing

## Date

24 August 2026

## Topic

Black Box Testing vs White Box Testing

## What I Learned

Today, I learned about two important software testing approaches: Black Box Testing and White Box Testing.

Black Box Testing focuses on testing the functionality and behaviour of an application without requiring knowledge of its internal source code.

White Box Testing focuses on the internal structure, code, and logic of an application.

I learned that the main difference can be summarized as:

> Black Box Testing = What does the software do?

> White Box Testing = How does the software work internally?

## Black Box Testing Techniques Learned

- Equivalence Partitioning
- Boundary Value Analysis
- Decision Table Testing
- State Transition Testing

## White Box Testing Techniques Learned

- Statement Coverage
- Branch Coverage
- Path Testing

## Practical Exercises Completed

## My Current QA Perspective

As a Manual QA Tester, most of my current work focuses on Black Box Testing because I test the functionality and behaviour of applications based on requirements and expected results.

However, understanding White Box Testing can help me better understand technical risks, communicate with developers, and improve my testing approach.

## Key Takeaway

> Black Box Testing tests what the software does.

> White Box Testing tests how the software works internally.
