## Topic

Risk-Based Testing

## What I Learned

Today, I learned about Risk-Based Testing and how QA testers can prioritize testing when time and resources are limited.

Risk-Based Testing does not mean that low-risk features should be ignored.

Instead, it means that features with greater risk should receive more testing attention.

I learned that two important factors used to evaluate risk are:

- Likelihood
- Impact

Likelihood answers:

> How likely is this feature or area to fail?

Impact answers:

> How serious would the consequences be if it fails?

A simple way to remember this is:

> Risk = Likelihood × Impact

## Examples of High-Risk Features

In an e-commerce application, examples of high-risk features include:

- Payment
- Checkout
- Cart
- User Authentication

Failures in these features could directly affect users and the business.

## Examples of Lower-Risk Features

Examples include:

- Footer text
- Minor visual issues
- Profile theme colour

These issues may still need testing, but they generally receive lower priority when testing time is limited.

## Key Takeaway

> QA is not only about testing everything.

> It is also about understanding risk and making smart decisions about where to focus testing effort.

When time is limited, I should prioritize features that are most likely to fail and would have the greatest impact if they fail.
