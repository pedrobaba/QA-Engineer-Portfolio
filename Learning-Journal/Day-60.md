
# Day 60 Learning Journal — Test Management & QA Documentation

## What I Learned

Today, I studied test management and the purpose of essential QA documents. I learned how test plans, test scenarios, test cases, bug reports, test execution reports, test summary reports, and Requirements Traceability Matrices support different parts of the testing process.

I also practiced calculating test pass rates and communicating test results, open defects, blockers, and risks.

## Key Lessons

- A Test Plan defines the overall testing approach.
- A Test Case contains steps and expected results.
- A Test Execution Report records the outcomes of executed tests.
- A Test Summary Report communicates overall testing results and remaining risks.
- An RTM connects requirements to test cases and helps identify coverage gaps.
- A Bug Report documents an observed defect for investigation.
- A blocked test must not be recorded as passed.
- QA status updates should distinguish observed facts from assumptions.

## Practical Exercise

I worked through a simulated registration-testing scenario involving 20 test cases:

- 16 passed.
- 3 failed.
- 1 was blocked.
- 2 defects remained open.
- Email verification was untested because the test email service was unavailable.

I calculated the pass rate as:

(16 / 20) × 100 = 80%

I also drafted a QA status update that communicated the results, open defects, blocker, remaining risk, and recommended next steps.

## Challenge

I initially found it difficult to distinguish a Test Case from a Test Execution Report. I reinforced the difference by identifying whether a document defines how to test a feature or records what happened after the test was run.

## Improvement for Next Time

I will continue practicing how to select the appropriate QA document, maintain traceability, and report results accurately without confusing a blocker with a defect or an assumption with an observed fact.

## Reflection

Today reinforced that testing is not only about executing test cases. It also involves maintaining clear records, communicating evidence, tracking unresolved issues, and helping stakeholders understand the product's remaining risks.
