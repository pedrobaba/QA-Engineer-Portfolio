# Day 70 — Learning Journal

## Topic
QA Portfolio Project — Planning

## What I Learned

Today I learned how to plan a structured QA portfolio project using SauceDemo.

I learned that testing should begin with a clear understanding of the application, its users, business workflows and testing objectives.

I also learned the importance of defining scope and testing boundaries to prevent unnecessary testing activities.

## Key Concepts

1. A project objective explains what the testing project intends to achieve.
2. Scope defines what is included and excluded.
3. Test scenarios describe what needs to be tested.
4. Test cases provide detailed execution instructions.
5. Test data supplies the inputs needed for testing.
6. Testing types help determine how application behaviour should be evaluated.
7. Exit criteria establish when testing can reasonably conclude.
8. Test deliverables are the documents and outputs produced during testing.

## Practical Application

I planned a SauceDemo testing project covering:

- Authentication
- Inventory
- Product sorting
- Shopping cart
- Checkout
- Order completion
- Logout

I also identified 22 initial test scenarios and established a proposed GitHub project structure.

## Connection to Automation Testing

The manual test cases developed during this project will become the foundation for future Playwright automation.

For example, a manual login test can later be converted into an automated browser test using Playwright locators and assertions.

## Challenges and Observations

One important lesson is that planning a test is different from executing it.

A test case should not be marked as passed or failed until it has actually been executed and its actual result recorded.
