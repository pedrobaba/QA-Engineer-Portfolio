Today, I learned how manual test execution works and how QA engineers record the results of executed test cases.

I understood the difference between expected and actual results and how to assign the correct execution status.

I also learned how to handle failed and blocked test cases, investigate unexpected behaviour, capture evidence, and prepare a test execution report.

- Expected vs actual results

- Test execution reporting

- Pass rate

### Challenges and Lessons

One important lesson was that a failed test does not automatically confirm a software defect. The tester must investigate the issue, verify the test data and environment, and attempt to reproduce the unexpected behaviour.

I also learned that a test should remain Not Run until it has actually been executed.

### Interview Preparation

I practised explaining:

- What test execution means.
- The difference between a test case and test execution.
- How to handle failed test cases.
- The difference between a failed and blocked test.
- What a test execution report contains.
- The difference between execution rate and pass rate.
