# Day 75 — Learning Journal: Test Summary Report

## What I Learned

Today, I learned how to prepare and interpret a Test Summary Report.

I understood that a TSR provides stakeholders with an overview of the testing process and its outcomes.

I also learned how to calculate execution rate, pass rate, failure rate and blocked rate.

## Key Concepts Practised

- Test Summary Report structure
- Test execution metrics
- Defect summary
- Severity vs priority
- Testing risks
- Release readiness
- QA recommendations

## Practical Application

I applied these concepts to my SauceDemo QA portfolio project.

I prepared an initial Test Summary Report covering the project overview, testing objectives, scope, execution statistics, defect summary, risks and recommendations.

The report currently records 22 test cases as Not Run because I have not yet completed live execution.

I also maintained the distinction between simulated bug-report examples and verified defects.

## Challenges and Lessons

One important lesson was that a high pass rate does not automatically mean an application is ready for release.

QA must investigate unresolved defects, review critical workflows and communicate outstanding risks.

I also learned that accurate reporting is more important than presenting impressive testing statistics.
