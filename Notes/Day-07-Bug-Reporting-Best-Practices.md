# What is a Bug Report?

A bug report is a document that describes a software defect so that developers can reproduce, investigate, and fix it.

---

# A Professional Bug Report Should Include

- Bug ID
- Title
- Module
- Environment
- Preconditions
- Steps to Reproduce
- Expected Result
- Actual Result
- Severity
- Priority
- Attachments (Screenshots or Videos)
- Additional Notes (if required)

---

# Characteristics of a Good Bug Report

- Clear
- Concise
- Reproducible
- Accurate
- Well organised
- Supported with evidence

---

# Example of a Good Bug Title

❌ Poor

Login Error

✅ Better

Login displays an "Invalid Username or Password" message when valid credentials are entered.

---

# Common Reasons Bug Reports Are Rejected

- Unable to reproduce
- Duplicate report
- Missing screenshots or recordings
- Missing reproduction steps
- Insufficient information
- Expected behaviour mistaken for a defect

---

# Best Practices

- Verify the issue before reporting.
- Use descriptive titles.
- Include precise reproduction steps.
- Attach screenshots or videos whenever possible.
- Assign the correct severity and priority.
- Avoid assumptions; report only observable behaviour.

---

# Key Takeaways

Writing a high-quality bug report helps developers reproduce issues quickly, reduces back-and-forth communication, and speeds up defect resolution.
