# Day 10 – Test Plan

## What is a Test Plan?

A Test Plan is a formal document that outlines the scope, objectives, strategy, schedule, resources, and approach for testing a software application. It serves as a roadmap for the QA team throughout the testing process.

---

## Objectives of a Test Plan

- Define the scope of testing.
- Identify features to be tested.
- Specify testing approach.
- Assign responsibilities.
- Estimate testing effort and schedule.
- Identify risks and mitigation strategies.

---

## Components of a Test Plan

1. Test Plan ID
2. Project Overview
3. Objectives
4. Scope
5. Features to Test
6. Features Not to Test
7. Test Environment
8. Test Approach
9. Entry Criteria
10. Exit Criteria
11. Risks
12. Deliverables
13. Schedule
14. Team Responsibilities

---

## Benefits

- Keeps the testing process organized.
- Improves communication among team members.
- Reduces project risks.
- Ensures complete test coverage.
- Helps track testing progress.

---

## Example

Project: SauceDemo

Objective:
Verify that all major functionalities of the SauceDemo application work as expected before release.

Scope:
- Login
- Product Listing
- Shopping Cart
- Checkout
- Logout

Deliverables:
- Test Cases
- Test Reports
- Bug Reports
- Test Summary Report

---

## Key Takeaway

A Test Plan acts as the blueprint for the testing process. It defines what needs to be tested, how testing will be performed, and when testing is considered complete.
