# Day 10 – Test Strategy

## What is a Test Strategy?

A Test Strategy is a high-level document that defines the overall approach to software testing. It establishes the testing objectives, standards, methods, and processes that will be followed throughout the project or organization.

Unlike a Test Plan, a Test Strategy is generally reusable across multiple projects.

---

## Objectives

- Define the overall testing approach.
- Maintain consistency across projects.
- Improve software quality.
- Ensure complete test coverage.

---

## Components

- Testing Objectives
- Scope
- Test Levels
- Test Types
- Test Environment
- Risk Management
- Entry & Exit Criteria
- Tools
- Roles & Responsibilities

---

## Test Levels

- Unit Testing
- Integration Testing
- System Testing
- User Acceptance Testing (UAT)

---

## Test Types

- Functional Testing
- Regression Testing
- Smoke Testing
- Sanity Testing
- Exploratory Testing
- Performance Testing
- Security Testing

---

## Difference Between Test Strategy and Test Plan

| Test Strategy | Test Plan |
|---------------|-----------|
| High-level document | Project-specific document |
| Long-term | Short-term |
| Defines overall approach | Defines execution plan |
| Usually created once | Created for every project |

---

## Key Takeaway

A Test Strategy defines **how an organization approaches testing**, while a Test Plan explains **how testing will be carried out for a specific project**.
