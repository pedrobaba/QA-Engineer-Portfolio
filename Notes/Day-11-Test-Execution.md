# Day 11 - Test Execution

## What is Test Execution?

Test Execution is the process of running test cases to verify whether the actual behavior of an application matches the expected behavior.

During test execution, QA engineers:
- Execute prepared test cases.
- Compare actual results with expected results.
- Record the outcome of each test.
- Report any defects found.
- Attach evidence when necessary.

---

## Test Execution Workflow

1. Prepare the test environment.
2. Execute test cases.
3. Compare actual and expected results.
4. Mark the test status.
5. Report defects if found.
6. Retest fixed defects.
7. Prepare a Test Summary Report.

---

## Test Execution Status

### ✅ Passed
The feature behaves exactly as expected.

### ❌ Failed
The feature does not behave as expected.

### ⛔ Blocked
Testing cannot continue because another issue prevents it.

Example:
- Login server is unavailable.

### ⏳ Not Executed
The test case has not been run.

Example:
- Testing has not started.
- The feature is not ready.

---

## Best Practices

- Follow test cases carefully.
- Record results immediately.
- Report defects clearly.
- Attach supporting evidence.
- Verify bug fixes during retesting.

---

## Key Takeaway

Test execution is not just about clicking through an application—it is about verifying requirements, documenting results accurately, and identifying defects that impact software quality.
