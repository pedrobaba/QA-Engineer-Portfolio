# Day 21 — Dynamic Testing

## What is Dynamic Testing?

Dynamic Testing is the process of executing software and verifying its actual behaviour against the expected result.

Unlike Static Testing, Dynamic Testing requires the application or component being tested to be executed.

## Key Characteristics

- The software is executed.
- Actual results are compared with expected results.
- It validates application behaviour.
- It can identify defects during execution.
- It requires a testable application or component.

## Examples of Dynamic Testing

- Testing a login feature
- Testing a registration form
- Adding a product to a cart
- Testing the checkout process
- Sending an API request
- Validating an API response

## Example

### Login Test

1. Open the application.
2. Enter valid username and password.
3. Click the Login button.
4. Verify that the user is successfully logged in.

This is Dynamic Testing because the application is executed.

## Static vs Dynamic Testing

| Static Testing | Dynamic Testing |
|---|---|
| Software is not executed | Software is executed |
| Reviews work products | Tests actual behaviour |
| Finds issues early | Finds defects during execution |
| Requirements and documents can be reviewed | A testable application or component is required |
| Example: Reviewing requirements | Example: Testing login |

## Key Takeaway

Dynamic Testing validates how the software actually behaves by executing it and comparing the actual result with the expected result.
