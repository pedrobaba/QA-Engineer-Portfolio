# Day 21 — Static Testing

## What is Static Testing?

Static Testing is the process of reviewing software-related work products without executing the software.

It can be used to identify issues in requirements, documents, designs, test cases, and source code before the application is executed.

## Key Characteristics

- The software is not executed.
- It involves reviewing and examining work products.
- It can help identify defects early.
- It can reduce rework and development costs.
- It helps identify unclear or missing requirements.

## Examples of Static Testing

- Reviewing requirement documents
- Reviewing user stories
- Reviewing acceptance criteria
- Reviewing test cases
- Reviewing test plans
- Reviewing design documents
- Reviewing source code without executing it

## Types of Reviews

### Informal Review

A simple review performed without a formal process or defined roles.

### Walkthrough

A review where the author presents and explains a document or work product to the team to collect feedback.

### Technical Review

A structured review performed by people with relevant technical knowledge to evaluate a technical work product.

### Inspection

A formal and systematic review process with defined roles used to identify defects.

## Benefits of Static Testing

- Finds defects early
- Improves requirement quality
- Reduces rework
- Helps prevent misunderstandings
- Improves communication between team members

## Example

Requirement:

> Users should be able to complete checkout quickly.

This requirement is unclear because the word "quickly" is not measurable.

A better requirement could be:

> The checkout page should load within 3 seconds under defined test conditions.

## Key Takeaway

Static Testing helps QA teams identify issues before software execution by reviewing requirements and other work products.
