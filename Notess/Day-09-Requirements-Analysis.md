# Day 09 - Requirements Analysis

## What is Requirement Analysis?

Requirement Analysis is the process of understanding, reviewing, and validating software requirements before testing begins.

It helps QA Engineers identify:
- What needs to be tested.
- What the expected behaviour should be.
- Any missing or unclear requirements.

---

## Why Requirement Analysis is Important

- Prevents misunderstandings.
- Helps create accurate test cases.
- Identifies ambiguities early.
- Ensures complete test coverage.
- Reduces defects caused by incorrect implementation.

---

## Responsibilities of a QA Engineer

- Review business requirements.
- Ask clarification questions.
- Identify missing requirements.
- Suggest improvements.
- Estimate testing effort.
- Design test scenarios and test cases based on requirements.

---

## Example Requirement

Requirement:
Users should be able to log in using a valid email address and password.

Possible Test Scenarios:

- Verify login with valid credentials.
- Verify login with an invalid email.
- Verify login with an invalid password.
- Verify login with empty fields.
- Verify error messages.

---

## Key Takeaway

Good testing starts with understanding the requirements before writing test cases.
