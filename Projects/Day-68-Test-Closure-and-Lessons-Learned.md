Day 68 — Practical Project: Test Closure & Lessons Learned

Project Overview

This project demonstrates how a QA tester can prepare a test closure summary, review final test execution results, document outstanding defects, and capture lessons learned.

The exercise uses simulated e-commerce testing data.

Project type: Simulated QA exercise
Application: Sample e-commerce application
Tools: Markdown and manual calculations

Project Objectives

* Prepare a test closure summary.
* Calculate execution coverage and pass rate.
* Review unresolved defects.
* Identify outstanding release risks.
* Document lessons learned.
* Provide a QA closure recommendation.

⸻

1. Test Execution Summary

Sample Test Results

Metric	Result
Planned test cases	100
Executed test cases	95
Passed	85
Failed	10
Not executed	5

Execution Coverage

Execution Coverage =
(Executed / Planned) × 100
= (95 / 100) × 100
= 95%

Pass Rate

Pass Rate =
(Passed / Executed) × 100
= (85 / 95) × 100
= 89.47%

Interpretation

The team executed 95% of the planned test cases.

Of the executed test cases, 89.47% passed and the remaining 10.53% failed.

Five planned test cases were not executed and should be accounted for in the final report.

2. Outstanding Defect Review

Scenario

The application has two unresolved high-severity defects.

Defect ID	Description	Severity	Status
BUG-101	Checkout fails under a specific payment condition	High	Open
BUG-102	Order confirmation displays incorrect information	High	Open

QA Review

Both defects should remain visible in the final defect report.

The QA team should:

1. Confirm that the defects are reproducible.
2. Review their impact.
3. Ensure the defect records are complete.
4. Communicate the outstanding risks.
5. Recommend appropriate follow-up actions.

The final release decision should consider the actual impact and agreed release criteria.

4. Lessons Learned Report

What Went Well

* Test execution results were recorded.
* Defects were documented.
* Final testing metrics were calculated.
* Outstanding risks were identified.

What Could Be Improved

* Some requirements required clarification.
* Some test cases needed repeated execution.
* Some defect reports required clearer supporting evidence.
* Defect escalation could be improved.

Recommended Improvements

Observation	Recommended Action
Unclear requirements	Clarify acceptance criteria before test design
Repeated test execution	Improve test case organisation
Incomplete defect evidence	Include screenshots and reproduction steps
Late defect escalation	Define an escalation process
Unexecuted test cases	Document reasons and associated risks

Closure Assessment

The testing activities and reporting work have been completed in this exercise.

However, the unresolved high-severity defects still require formal review against the project’s closure and release criteria.

The checklist therefore distinguishes completed reporting activities from pending risk decisions.
