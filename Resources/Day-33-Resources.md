# Day 33 — Learning Resources

## 📚 Resources Used

### 1. SQLBolt

**Topic:** SQL SELECT, WHERE, ORDER BY, and filtering practice

**What I used it for:**
Practicing SQL queries and understanding how filtering and sorting work together.

**Key things learned:**

* Using `WHERE` to filter records.
* Using `ORDER BY` to sort query results.
* Using `ASC` for ascending order.
* Using `DESC` for descending order.
* Combining filtering and sorting in the same query.

---

### 2. W3Schools — SQL ORDER BY

**Topic:** Sorting query results

**What I used it for:**
Reviewing how `ORDER BY`, `ASC`, and `DESC` are used in SQL.

**Key things learned:**

* `ORDER BY` is used to sort results.
* `ASC` sorts from lowest to highest / A to Z.
* `DESC` sorts from highest to lowest / Z to A.
* `WHERE` can be used before `ORDER BY` to filter records before sorting them.

---

### 3. W3Schools — SQL WHERE

**Topic:** Filtering records

**What I used it for:**
Reviewing how SQL filtering works before applying sorting.

**Key things learned:**

* `WHERE` is used to specify conditions.
* Multiple conditions can be combined.
* Filtering helps narrow database results to the records needed for investigation.

---

## 🧪 Practical Application

I applied the concepts from these resources to SQL exercises using a `users` table.

I practiced:

* Filtering users with `WHERE`
* Sorting users with `ORDER BY`
* Using `ASC` and `DESC`
* Combining `WHERE` with `ORDER BY`
* Applying SQL filtering and sorting to QA-style data validation

---

## 💡 QA Relevance

SQL filtering and sorting can help a QA Engineer investigate application data.

For example, after testing a user-management feature, SQL can be used to:

* Find specific users.
* Check whether expected records exist.
* Identify missing information.
* Filter records based on conditions.
* Sort records to make investigation easier.
* Support database validation when investigating bugs.

---

## 📝 Personal Note

The main lesson from Day 33 was understanding that SQL clauses have different responsibilities.

**WHERE → filters data**

**ORDER BY → sorts data**

Understanding this distinction helps me write clearer SQL queries and investigate database-related issues more effectively.
