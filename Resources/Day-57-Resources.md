## Day 57 — Smoke & Sanity Testing Practice

### Learning Focus

- Smoke testing and build readiness
- Sanity testing after a focused change or bug fix
- Selecting appropriate testing scenarios
- Handling failed smoke tests
- Writing expected and actual results
- Recording test status, environment, and evidence

### Learning Resources

1. **Atlassian — Types of Software Testing**  
   https://www.atlassian.com/continuous-delivery/software-testing/types-of-software-testing

2. **ISTQB Glossary**  
   https://glossary.istqb.org/

Use these resources to review software testing terminology and the role of different testing approaches.

### Practice Notes

- Start with critical application functions when assessing a new build.
- Focus on the affected functionality when checking a specific fix.
- Report failed smoke tests promptly.
- Include expected results, actual results, test status, and relevant environment details.
- Capture evidence when a failure is reproduced.
- Follow the team's process for deciding whether further testing should proceed.
- Distinguish simulated practice from actual test execution.
